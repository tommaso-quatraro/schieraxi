# Ondata 2: testi da una fonte, web a moduli, prova online, controlli visivi e di contratto, limiti per utente: piano

> **Per chi esegue:** OBBLIGATORIA la skill `superpowers:subagent-driven-development` (consigliata) o `superpowers:executing-plans`,
> un compito alla volta. Ogni lavoro (A1, B1, …) è un ramo e una PR sua, in una worktree sua. Passi con `- [ ]`. I confini dei
> file (§1) non si superano: se un compito ha bisogno di un file che non è suo, si ferma e lo scrive nel rapporto.

**Obiettivo:** i sette lavori dell'ondata 2 decisi dall'utente il 6/11 (a-g), divisi in PR piccole che possono andare in parallelo
senza file in comune.

modulo d'ingresso con i moduli in `fanta/web/moduli/`; due controlli nuovi (aspetto della web, contratto iPhone-server) girano in
ogni PR; l'ambiente di prova è una seconda copia dell'app sullo stesso server, proposta qui e accesa solo con l'ok dell'utente;
i limiti per utente stanno in `fanta/limiti.py`.

**Strumenti:** Python 3.12 della libreria standard (più Pillow, già nei requisiti dei test), Playwright in un ambiente a parte con
versione e hash fissati, Chrome di sistema, bash per gli script del server, Swift Testing per i test iOS nuovi.

## Attenzione in revisione

Casi che la spec implica e che è facile lasciar scappare; ognuno ha il suo test nel compito indicato.
1. **Un nome usato da uno script classico non arriva da `window`** dopo lo spostamento in un modulo: il tocco non fa niente e
   l'errore compare solo al clic. Atteso: ogni nome usato da script classici, `index.html` o `prove/foto_web/foto.py` è su `window`.
   Test `test_ogni_nome_usato_fuori_dai_moduli_e_su_window` (B1, rifatto in ogni B).
2. **Telefono con la web installata e la copia vecchia in cache** dopo l'aggiornamento: pagina bianca se manca un modulo. Atteso:
   ogni modulo importato sta nella scocca di `sw.js` ed è pubblico senza sessione. Test `test_ogni_modulo_e_nella_scocca_e_pubblico` (B1).
3. **Testi con `"`, `\`, a capo, emoji, `{n}` o «…»** nel catalogo: un errore di escape spegne tutta la web o non compila l'iPhone.
   Atteso: `testi.js` generato si legge con node e dà lo stesso testo; Swift con le stesse stringhe. Test
   `test_testi_difficili_tornano_uguali` (A1).
4. **L'ambiente di prova scrive nella produzione** o cambia il comportamento di `aggiorna-app.sh` senza `SCHIERAXI_ISTANZA`.
   Atteso: senza istanza, configurazione identica a oggi; con `prova`, ogni percorso sotto le cartelle della prova. Test
   `test_senza_istanza_tutto_come_oggi` e `test_prova_tutto_nelle_sue_cartelle` (C1).
5. **Un utente normale vede «Troppe richieste»**: la propria formazione, tre giornate, quattro squadre avversarie, qualche ricarica.
   Atteso: mai 429. Test `test_uso_normale_non_incontra_limiti` (G1).

## 3. Compiti

### (a) Catalogo unico dei testi

#### A1. Catalogo, generatore, `testi.js` generato
**Interfacce prodotte** (in `script/testi.py`, usate da A2-A5 e da chi aggiunge testi):
- `carica_catalogo(cartella: Path) -> dict[str, dict[str, Voce]]` (prefisso → chiave → `Voce(it: str, en: str, nota: str | None)`),
  con errori in italiano per: chiave nel file sbagliato, lingua mancante o vuota, segnaposto diversi fra `it` e `en`, coppia plurale
  incompleta, chiave in due file.
- `blocco_testi_js(catalogo) -> str`: l'istruzione `const TESTI = { it: {…}, en: {…} };`, una chiave per riga nella forma
  `    "chiave": "testo",` (stringa JSON con `ensure_ascii=False`), file in ordine alfabetico, chiavi nell'ordine del file, una riga vuota
  fra un file e l'altro.
- Righe-segno in `testi.js`: `// <catalogo> generato da script/testi.py: non modificare a mano` e `// </catalogo>`.
- `chiavi_ios(cartella: Path) -> dict[str, list[str]]` da `ios/testi/<prefisso>.txt` (una chiave per riga, `#` = commento;
  cartella assente = nessuna chiave).
- `swift(catalogo, chiavi) -> dict[str, str]` (nome del file → testo): `Catalogo.swift` con `enum Catalogo {}` e un file per prefisso
  `<Prefisso>.swift` con `extension Catalogo { enum <Prefisso> { … } }`. Regole dei nomi: `oggi.tua_formazione` →

## 6. Rischi

- **A1, diff grande su `testi.js`:** ogni PR web aperta che aggiunge testi entra in conflitto. Si apre A1 quando nessuna lo tocca;
  dopo l'unione il test dice alle altre di spostare i testi nel catalogo.
- **B, finestra su `app.js`:** 2-3 giorni in cui le altre PR della web aspettano. Ordine dei moduli, nomi su `window`, nomi importati
  riassegnati e cache del service worker hanno ognuno il suo test; la regressione visiva fa da rete.
- **B1, tipo dei file `.js`** sul server locale di Windows [da verificare]: se è sbagliato i moduli non partono; c'è il test e la riga di rimedio.
- **C, memoria del server:** una seconda copia del modello può non starci [da verificare in 4.1]; `MemoryMax` la ferma prima che tocchi
  la produzione; in quel caso la prova diventa «accesa solo per il collaudo».
- **C1, script installato da solo:** un errore in `aggiorna-app.sh` arriva in produzione. Per questo la PR resta in bozza fino all'ok e
  il test confronta la configurazione senza istanza con quella di oggi.
- **D, foto instabili** (caratteri, animazioni, orologio): prova di stabilità prima, elenco `INSTABILI`, e il controllo resta in avviso
  finché non è affidabile.
- **D, risposte registrate incomplete:** alcune parti delle scene restano vuote (novità, avatar): il confronto vale lo stesso; le rotte
  mancanti stanno nel riassunto e si aggiungono alla prossima registrazione.
- **E, grafo rumoroso:** i componenti comuni raggiungono tutto; oltre 12 schermate vale «principali», come oggi.
- **F, falsi allarmi** per proprietà riempite sul telefono: eccezioni con il motivo, controllate perché non restino vecchie.
- **G, limiti troppo stretti:** test dell'uso normale; numeri cambiabili con una variabile d'ambiente senza codice.
- **G4, scrittura sicura toccata al centro:** `scrivi_sicuro` serve a tutto; il test che le scritture degli utenti vivi non cambiano è obbligatorio.
